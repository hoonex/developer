# Web Design Guidance — source notes

`web-design-guidance` is an independently written Sloar companion. It does not vendor or require the projects below. Its structure was informed by publicly available design-agent projects reviewed during development:

- `nextlevelbuilder/ui-ux-pro-max-skill` — product-aware design-system recommendation, style/typography/color/anti-pattern categorization, responsive and pre-delivery checks.
- `superdesigndev/superdesign-skill` — persistent repository-aware design-system memory and design-system extraction/setup concepts.
- `educlopez/ui-craft` — surface-oriented design workflows, acceptance bars, rendered self-review, and anti-generic generated-UI thinking.
- `rwcod/anti-ai-slop-ui` (MIT) — product-specific direction before implementation, explicit catalogs of common generated/default UI tells, and anti-slop/distinctiveness review concepts.
- `funboy322/avoid-ai-design` (MIT) — code-vs-render evidence separation, P0/P1/P2 severity, contextual exemptions, second-order-default detection, and the principle that a clean cliché checklist is necessary but not sufficient for a strong design.
- `imMamdouhaboammar/unslop-preflight` — vague-request preflight, design-readiness thinking, and separating specification quality from implementation quality.
- public `frontend-design` skill variants were reviewed for the idea of committing to a coherent aesthetic direction; Sloar deliberately does not adopt a universal requirement that every interface be bold, extreme, or visually memorable.

The original repositories and licenses remain authoritative for their respective works. No external runtime dependency is introduced by this companion, and source text/assets are not vendored here.

Sloar's companion generalizes the ideas around repository precedence, adaptive clarification, multi-axis design reasoning, visual evidence, anti-default auditing, resilience, and bounded work. Target-repository design rules always take precedence.
